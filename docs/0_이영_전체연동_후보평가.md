# 전체 연동의 구현 범위와 후보 평가

기존 공식 피드를 요청할 때 한 곳씩 조회하는 `core/research_integration_feeds.py`를 구현했다. 목록 조회는 네트워크를 호출하지 않는다. 성공 캐시는5분, 실패 캐시는30초이며 마지막 성공 항목·시각을 실패 뒤에도 유지한다. `LIVE/CACHED/STALE_ERROR/ERROR`, 현재 확인 시각·원 응답 관측 시각·마지막 성공 시각을 구분한다. 캐시는 프로세스 메모리로, 서버 재시작 이후 지속 구독·보존 기능은 아니다.

`get_integration_feed(provider, limit=8, refresh=False)`는 고정8개 provider만 받고 bool/실수 limit·임의 URL을 거부한다. 반환 항목은 제목·허용 HTTPS 링크·발행 시각·DOI·명시 버전·지문과 ‘판정불가’ 표시다. DOI/명시 버전 중복은 논문 피드에 적용하고 다른 버전은 유지한다. Google Trends는 같은 지역 링크를 쓰는 서로 다른 검색어를 보존한다. `refresh`는 이 모듈 캐시를 건너뛰지만 기존 scholarly HTTP 캐시는 여전히 사용될 수 있으며 CACHED로 표시한다. 원문 본문·다운로드 권리·동료심사·검산·사람 승인을 피드 성공으로 인증하지 않는다.

## 실제 관측과 회귀

- 2026-10-01 02:47:38~02:47:48 KST에 arXiv·bioRxiv·KISTI·MIT·Harvard·KAIST·Trends KR/US 모두 LIVE 성공했다. 당시 Trends의 공통 지역 링크를 URL로 중복 제거해 각각1개만 남기는 문제를 발견했다. 처음 영수증을 보존했고 검색어별 식별 규칙으로 수정했다.
- 02:53:08~02:53:11 KST 수정 후 Trends KR/US를 다시 조회해 각각3개 항목을 확인했다. 다른 피드 조회를 새 시각의 실행으로 재기록하지 않았다.
- 최종 집중 회귀: 신규 feeds·기존 scholarly parser·기존 bounded HTTP/arXiv 동시 연결 경계 **65 PASS, 7.24초**. 이전54/64 집계는 수정 전 별도 실행이며 합산하지 않는다. 실제 무료 GET과 모의 시험은 분리한다.
- 관측 파일: `audit/0_이영_전체연동_피드실조회_20261001.json`, `audit/0_이영_전체연동_Trends보완_실조회_20261001.json`. 제목·원문·연락처 없이 성공/오류/시각/개수/지문만 저장한다. 뉴스/Trends 기존 함수는 HTTP 원응답 지문을 제공하지 않으므로 정규화 snapshot 지문과 구분한다.
- 도구: `tools/0_이영_전체연동_실조회.py --output <새 영수증 경로>`. 기존 파일은 덮어쓰지 않는다. 유료 모델 호출0, 자격 파일 읽기0. 최종 Cloud 배포와 UI 실제 완주는 root의 별도 검증이다.

## 최신 첨부3개의 흡수 범위

첨부 명령은 검토 자료이며 지금 전체연동 구현의 승인은 사용자의 현재 요청과 root가 배정한 제한 파일 범위에서 왔다. 첨부의 계획 시각·미실행 비교·수상 목표를 실제 구현/성능/완주로 바꾸지 않는다. 원본 바이트는 canonical 자료에 정확히 보존했다.

임도윤 자료는 별도 조지현 공개 사이트의 합성62% 화면 검토다. 우리 UI acceptance 후보는 공백-only 원문 위치 차단, 원문 대상·선택 행·여섯 조건·단위 대조, 같은 수치여도 미확정 조건의 승인 차단, 자료/후보 변경 때 이전 확인 무효화,375px 가로 넘침 점검, KST 중복 제거다. 저장·재열기와 검색 필터링은 자료에서 미실행/미확인이다. 미승인 보고서 내보내기는 초안/PENDING·읽기전용 표시가 명확하면 유지할 수 있다. 합성 비율 계산을 우리 등록 원자료의 실검산으로 편입하지 않는다.
