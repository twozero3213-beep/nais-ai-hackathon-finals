작성일: 2026-09-30 KST. 상태: 계획, 아래 시험은 이 문서 작성 작업에서 미실행.

## 1. 설계 문서와 연결

[조건 추출 규격](../finals-strategy/extraction.schema.json)은 행 수와 평균을 지원 대상으로 정한다. [8사례 비교 계획](../finals-strategy/comparison-protocol.json)은 정상 2, 계산 불일치 2, 근거 부족 2, 자료 변경 2를 정의한다. 이 문서는 두 계약을 바꾸지 않으며 제품 통합 전에 확인할 검사 순서를 추가한다.

아래 경로와 함수는 구현 연결을 검토할 대상이다. 조회한 팀 저장소에는 제품 코드가 아직 없으므로 배포된 기능으로 해석하지 않는다. 코드 통합과 실제 시험 결과는 별도 작업으로 기록한다.

| 순서 | 검사할 문제 | 재사용 후보 파일·함수 | 완료 기준 | 상태 |
| --- | --- | --- | --- | --- |
| 1 | 숫자 형식 오류가 결측값으로 조용히 빠짐 | 숫자 변환·평균 계산 연결부를 우선 추적, 정확한 함수는 재현 후 확정 | 쉼표 숫자·잘못된 문자열·결측 표기를 구분. 미지원 형식은 명시적으로 거절. 정상 평균도 유지 | 팀 문서의 재현 보고 있음, 이 작업에서는 재현 미실행 |

숫자 형식 문제의 근거는 [팀 사례 팩트체크의 제품 자체 점검](../3_조지현_필요성_차별점_사례팩트체크.md)이다. 해당 보고를 이 담당자의 신규 재현 결과로 표시하지 않는다. 원문과 원출력의 연결을 확인한 뒤 수정한다.

## 2. 최소 시험 설계

- 평균 검사: `[10, 20, 30]`의 기대 평균 20. 합성 손계산 기준이며 실행 성과가 아니다.
- 형식 검사: `1,000`을 허용할지 명세로 먼저 정한다. 허용하면 1000으로 변환하고, 지원하지 않으면 오류를 알린다. 조용히 누락하지 않는다.
- 식별자 검사: 기준 `[A,B,C]`에 정상 `[A,B,C]`, 역순 `[C,B,A]`, 중복 `[A,A,C]`, 누락 `[A,B]`를 넣는다. 기본 정책은 순서 차이 차단이다.
- 조건 부족 검사: 분모·대상 또는 원문 위치가 없으면 계산 가능 여부와 주장 검증 가능 여부를 구분해 보류한다.
- 변경 검사: 원본과 사전 고정한 변형 파일을 구분하고 변경 뒤 결과의 재사용 여부를 확인한다.
- 사람 승인 검사: AI 추출·계산·비평 성공만으로 승인 상태가 생성되지 않는다.

이 시험들은 제품 방어 규칙 시험이다. 실제 연구의 오류를 제품이 새로 발견했다는 증거가 아니다. 새 시험은 팀의 8사례 비교 결과에 몰래 추가하거나 유리한 사례로 교체하지 않는다.

## 3. 결과 기록 계약

실행 전에 입력·질문·정답·허용 오차·지원 정책을 고정하고 파일 지문을 기록한다. 비교 정답은 모델에 전달하지 않는다. 실행마다 코드 커밋, 입력 지문, 실제 한국 시각, 판정, 수치, 근거 위치, 보류 이유, 소요 시간, 실패 이유를 기록한다. 모델 호출이 있으면 모델 식별자·원출력·사용량을 기록하되 비밀키는 제외한다.

결과를 보고 정답이나 사례를 바꾸지 않는다. 수정 후 재실행은 새 실행 번호를 부여하고 첫 실패도 보존한다. 실행하지 않은 지표는 미실행, 측정하지 않은 비용은 미측정으로 둔다.
