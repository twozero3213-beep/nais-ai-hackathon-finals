### P4. 사례 A1 고정 실행과 자유도 판정
```
탐욕 연구(정정 2017-09-05)의 정정문에서 b·SE·t와 보고 자유도를 원문 인용과 함께 기대값으로 고정한다(실행 전에 봉인, 지문 기록).
- 판정: 계수·SE·t가 모두 일치하고 자유도도 같으면 MATCH. 계수는 일치하지만 자유도가 다르면 NEEDS_REVIEW("계수 일치 · 자유도 확인 필요").
- 원래 구문(재코딩 전 SES)과 정정 구문(재코딩 후)을 각각 실행해, 부호가 반대로 나오는 것을 기록한다.
- 원문 인용 대조 전에 공백과 유니코드 마이너스(−→-)를 정규화하되, 원문은 그대로 보관한다.
- 자료(OSF 92qkx)의 이용 조건을 확인하고, 조건이 불명확하면 링크와 지문만 둔다.
```

### P5. 행 대응 진단 출력
```
행 대응 검사가 예외 문장 하나 대신 진단 객체를 반환하게 한다.
- 진단 필드: {status, missing_in_data[], missing_in_reference[], duplicates_data[], duplicates_reference[], order_differs: bool, normalization_candidates[{from, to, rule}]}
- 정규화(공백↔밑줄, 대소문자)는 후보로만 제시하고, 사람이 승인해야 적용한다.
- 기존 시험의 차단 동작은 그대로 유지한다.
- 시험: 누락·중복·순서·표기 차이 각 1건.
```

### P6. 형식 오류 정책 통일
```
모든 계산 경로에서 숫자 변환 실패를 결측과 구분한다.
- 명시한 결측 표기(missing_tokens)와 빈 칸만 결측으로 본다.
- 그 밖의 변환 실패가 1개라도 있으면 BLOCK하고, 칸 수와 예시 값 3개를 보여준다.
- 재현 시험: ["10","20","1,000","N/A","30"]에서 missing_tokens=["N/A"]이면 "1,000" 때문에 BLOCK. 천 단위 쉼표 허용은 명세에 적었을 때만.
```

### P7. Crossref 철회·정정 확인
```
DOI 서지 조회 결과에 Crossref updated-by를 저장하고, type이 retraction·expression_of_concern·correction인 공지의 DOI와 날짜를 표시한다.
- 철회·우려 표명이면 그 논문을 근거로 한 판정은 NEEDS_REVIEW로 둔다. 자동 삭제하지 않는다.
- 시험(녹화 응답): 10.1111/evo.14483 → 우려 표명 2023-08-29와 철회 2023-11-24 표시. 10.1038/sdata.2016.120 → 정정 2017-09-05 표시.
```

### P9. AI 조건 제안 실호출 (예산 승인 후)
```
원문 인용·열 이름·자료 지문을 입력으로, 모델이 정규 명세(P2) JSON을 구조화 출력으로 돌려주게 한다.
- 공식 anthropic SDK를 쓴다. 기본 모델은 claude-opus-5-5다.
- output_config={"format": {"type": "json_schema", "schema": 정규명세}}로 받고, 응답에서 type=="text" 블록만 읽는다. max_tokens는 16000이다.
- temperature를 보내지 않는다. stop_reason이 refusal이거나 max_tokens면 BLOCK한다.
- 모델이 모르는 값은 unresolved에 넣게 하고, 추정으로 채운 값은 사람 확인 전 계산하지 않는다.
- 원응답 SHA-256, 모델 ID, 토큰 수, 사람 결정을 기록한다. 같은 사례를 AI 없는 경로(수동 명세)와 비교한다.
- 유료 호출 승인이 없으면 실행하지 말고 "미실행"으로 적는다.
```
