2. 혁신 설계와 한 문장 차별점

**선택은 S1 역할 분리 + S2 변경 재검증이다.** S3 공정한 비교와 S4 AI 기여도 분리는 같은 8사례 실행으로 묶는다. 남은 시간에는 행 수·단일 열 평균·동등 조건 필터의 완주를 먼저 확보한다. 통계 방법 확대·외부 검색 확대는 동결 이후 추가하지 않는다.

| 조합 | 구현·실험 범위 | 현재 상태·완료 조건 |
| --- | --- | --- |
| S1 역할 분리 | LLM(엘엘엠·대규모 언어 모델)이 조건 후보 제안 → 형식·의미 연결 검사 → 결정적 계산 → 비평 → 보류 또는 사람 판단 | 신규 파일 저장·통합 진행 중. 실제 호출 성공·원출력 없으면 AI 기여 미실행 |
| S2 변경 재검증 | 입력 지문·조건 지문이 달라지면 등록 결론과 승인 재사용 차단, 영향받는 주장만 재검산 | 변경 계산 코드 재사용. 자료·후보 변경, 승인 해제·재열기 시험 통과 |
| S3 동일 조건 비교 | 일반 AI, 우리 수동 경로, 우리 AI 경로에 동일 입력·질문·모델·호출·시간·출력 예산을 고정; 계산 도구 사용의 차이를 명시 | 입력·정답 봉인과 등록 로컬 8건 실행 완료. 두 AI 조건 16건 미실행. 실패·미실행도 표에 남김 |
| S4 AI 기여 분리 | 수동 대비 추출 필드 정확성·수정 개수·시간 비교 | 모의 응답 시험을 실제 모델 기여로 집계하지 않음 |

추출 계약은 `docs/finals-strategy/extraction.schema.json`을 재사용한다. JSON(제이슨·구조화 자료 형식)의 필수 필드는 아래와 같다. 이 표는 형식 요약이며 모델이 채운 값이 올바르다는 증거가 아니다.

| 코드 필드 | 뜻·계약 |
| --- | --- |
| `claim_id`, `reported_value` | 주장 식별자와 원문 보고값. 값이 없으면 `null`(널·미확정 값), 임의 보충 금지 |
| `variable` | 분석 열. `mean`에는 실제 열 이름 필수, 행 수에서는 의미가 확인된 경우 열 없음 허용 |
| `filters` | 대상 조건. `column`, `operator="eq"`, `value`만 허용. 빈 배열은 필터가 없다는 근거가 있을 때만 사용 |
| `missing_policy`, `missing_tokens` | 결측 처리와 결측 표기. `error`, `complete_case`, `not_applicable`, `null` 계약을 계산 어댑터와 대조 |
| `denominator` | 분모·대상 범위. 미확정을 전체 행으로 자동 대체하지 않음 |
| `method` | `count_rows`, `mean`, `null`. 지원 밖 방법은 보류 |
| `unit` | 수치 단위. 원문과 동일하며 임의 단위 변환 금지 |
| `source_location` | `source_id`, `locator`, `quote`. 실제 원문 위치와 그곳에 존재하는 인용 |
| `field_evidence` | 보고값·변수·필터·결측·분모·방법·단위별 원문 근거 |
| `unresolved` | 빠진 조건·충돌·확인 요청. 필수 조건이 남으면 계산 전 보류 |

입력 파일·지문·승인 기록은 로컬 코드가 생성하며 LLM이 임의 작성하지 못한다. 중복 키·추가 필드·비유한 숫자·응답 크기 초과·지원 밖 필터를 거절한다. 원문 인용의 실제 존재, 해당 위치와 인용의 관계, CSV(씨에스브이·쉼표로 구분한 표 파일)의 열·값, 분석 대상·단위·결측 조건을 따로 확인한다. 근거 없는 쪽 번호를 생성하지 않는다.

검사된 후보는 화면에 표시하고 사람이 원문과 조건을 확인한 뒤에만 검산 후보를 사용한다. 계산은 `core/verifier.py`·`core/statistics.py` 및 등록 검산 `audit_registry`의 허용 경로를 어댑터로 재사용한다. 임의 코드 실행은 제공하지 않는다. 비평 호출은 원문·후보·계산을 보고 누락·충돌을 제시하며, 동의가 사람 승인을 대신하지 않는다. 원문 연결이 불명확하면 수치 일치와 의미 미확정을 분리해 **보류**한다. 비평이 미실행이면 그 상태를 화면·보고서에 남기고 비평 완료로 표시하지 않는다.

`human_approval`(휴먼 어프루벌·사람 승인)은 `PENDING` 또는 `APPROVED` 상태를 가진 별도 객체다. `approve_report`는 직접 확인·이유·현재 지문을 확인해야 한다. 후보·입력·계산 조건이 바뀌면 검토와 승인을 무효화한다. 저장 보고서 재열기는 구조뿐 아니라 현재 입력 결속과 판정 일관성도 확인한다.

**한 문장 차별점:** “근거관문은 AI가 제안한 분석 조건을 원문과 원자료로 검산하고, 자료나 조건이 바뀌면 결론의 재사용을 멈추게 하는 연구 검증 에이전트입니다.”

일반 챗봇과의 3줄 비교:

- 일반 AI도 같은 원문·자료·도구로 정확한 계산과 보류를 할 수 있으므로 실제 같은 조건으로 비교한다.
- 우리 경로는 주장별 원문 위치·자료 지문·계산 조건·실행 기록·사람 판단을 함께 저장한다.
- 자료나 조건 변경 뒤에는 결론과 승인 재사용을 차단하고 필요한 주장만 다시 검산한다. 우위 여부는 미측정이다.

현장 장면 **가정**: 연구실 대학원생이 공동저자의 수정 CSV를 받은 뒤 성과 보고서의 표본 수와 평균을 확인한다. 같은 파일명이어도 내용 지문이 다르면 이미 확인한 수치를 다시 쓰지 않고, 영향을 받는 주장만 검산한다. 원문의 제외 기준이 없으면 그 조건을 연구책임자에게 확인 요청한다. 실제 연구자 인터뷰·시간 절감은 아직 측정하지 않았다.

3. 비교 실험 설계

팀의 `docs/finals-strategy/comparison-protocol.json`과 `observations-template.csv`를 재사용한다. **정상 2·계산 불일치 2·근거 부족 2·자료 변경 2**, 총 8사례와 3조건의 **24개 관측**이다. 22:11 봉인은 이 계획의 C01~C08을 그대로 사용했다. 등록 기대값에 대한 결정적 로컬 검산 8건과 두 AI 조건 16개 미실행을 구분한다. 이는 사람의 새 조건 매핑 시간이나 독립 연구 타당성을 측정한 것이 아니다. `finals/app.py`의 별도 8개 기능 회귀 사례와도 다른 실험이다. 실제 논문의 오류를 발견했다고 주장하지 않는다.

원본 자료는 수정하지 않는다. C03·C04·C06은 합성 규칙 시험이고 C07·C08은 사전 정의한 통제 변형이다. 일반 AI가 C08의 내용 동일성을 올바르게 설명하고 새 근거를 제시하면 성공으로 기록한다.

조건 A는 **일반 AI 단독**, B는 **우리 경로·LLM 없음**, C는 **우리 경로·LLM 있음**이다. A와 C는 같은 공급자·모델, 같은 원문·자료·질문·허용된 읽기 및 제한 산술 도구를 사용한다. 정답은 제공하지 않는다. 사례당 시스템 상한 120초, 최대 두 호출, 호출당 출력 1,800토큰을 실행 전에 확정하며 실제 공급자 요청 상한이 더 작으면 두 AI 조건에 함께 적용한다. 사람 검토는 모두 120초로 통일한다. 준비·시스템·사람 검토와 총시간을 별도로 기록한다. 모델·비용 상한·도구 계약이 다르면 동일 조건 결과로 합산하지 않는다.

봉인 순서:

1. 사례별 원문·자료·질문·등록 조건·기대 판정·허용 보류 사유를 파일로 저장한다.
2. 계산 담당과 검증 담당이 정답·대상·변형을 독립 확인한다. 정답은 모델 입력에 넣지 않는다.
3. `tools/compare_exploratory.py::freeze`를 재사용해 입력·질문·기대값·코드 커밋을 SHA-256으로 고정한다. 기존 두 조건 집계와 새 세 조건 집계를 혼동하지 않는다.
4. 봉인 파일과 지문을 커밋하고 그 뒤 실행한다. 계획 파일 지문은 실험 입력 봉인 완료의 증거가 아니다.
5. 각 사례·조건을 새 문맥에서 실행하고 원출력·도구 기록·실패·시간 초과를 모두 보존한다.
6. 결과를 본 뒤 정답을 수정하지 않는다. 구현 결함을 수정하면 새 코드 커밋과 실행 번호로 재실행하고 전 시도를 남긴다.

실행 오류는 감추지 않고 “현재 모델 생성이 외부 차단되어 수동 경로를 시연합니다”라고 말한다. 저장 원출력은 실제 기록이 확보된 경우에만 재생한다. 모의 응답·화면 캡처 재생을 실제 AI 실행이나 실제 조작 영상으로 표시하지 않는다.

집중 시연에서는 C01~C08, 원문·자료, 후보·검산, 직접 승인, 보고서만 노출한다. 팀 관리·기관 설정·대규모 평가·예약·외부 논문 검색·임의 파일 업로드·불필요한 메뉴는 보여주지 않는다. 메뉴 숨김이 인증·승인·입력 검사를 우회하지 않게 한다. 실제 기능 연결 전 메뉴를 열지 않고, 사용 불가 기능은 미확보로 표시한다.

당일 점검은 이채우가 화면·발표, 임도윤이 실행·복구, 조지현이 증거·제출을 맡고 이영이 최종 확인한다.

- 발표장 네트워크와 대체 연결, 로그인·세션 만료·예비 기기, 서버 키 존재·생성 권한·한도(값 비노출)를 확인한다.
- 브라우저 확대·화면 해상도·한글 가독성·키보드 조작·다운로드·보고서 재열기를 발표 기기에서 확인한다.
- 충전기·배터리·절전·알림 차단·예비 기기와 동일 동결 코드·동일 입력 지문을 확인한다.
- 실제 조작 영상을 확보하면 발표 기기·예비 기기·오프라인 저장의 3곳에 두고 재생·소리·전환을 확인한다.
- 정상·불일치·근거 부족·자료 변경 4분류를 직접 시험하고 사람이 승인하지 않은 결과의 승인 상태가 유지되는지 확인한다.
- 기능 동결 커밋·봉인 지문·시험 원출력·영상 실행 시각·최종 제출 파일과 제출 확인을 연결한다.
