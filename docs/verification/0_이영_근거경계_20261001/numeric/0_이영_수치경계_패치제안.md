## 실제 관측과 범위

고정 커밋 `a6729178963392249b14c9dfbd93bf28704262a4`(2026-10-01T05:11:08+09:00). 본 실험은 05:26:36 KST 봉인, 05:27:03 KST 완료한 10쌍·22입력이다. 교정 기대 회귀는 05:33:32 KST 봉인, 05:34:30 KST 완료한 12시험으로 예상대로 교정 기대 7개 실패·정상 통제 5개 성공·실행 오류 0개다. 두 묶음을 합산해 통과율을 만들지 않는다.

`source_gate=True`는 직접 함수에 주는 합성 전제, `semantic_confirmed=True`는 Claim의 명시적 입력 전제다. 실제 논문 검사·등록 loader·브라우저·최종 승인·유료 모델을 실행하지 않았다. `_validation.valid`, `_calculate`, `core.verify` 결과를 실제로 관측했으며 최종 승인 성공으로 부르지 않는다. 커밋과 대상 소스 지문은 실행 전후 동일하다.

### N08 — 큰 정수의 정확한 평균을 잘못된 계산값으로 일치 판정

- 입력: `[9007199254740992, 9007199254740994]`, 보고 정수 `9007199254740993`, 허용오차 `0`, 분모 `2`.
- 정확한 정수 산술 평균: `9007199254740993`.
- 실제 `_calculate`: `value=9007199254740992.0`, `delta=0.0`, `within_tolerance=True`, `denominator_matches=True`.
- 실제 합성 `_validation.valid=True`; 실제 core.verify는 `SUPPORTED`. 단순 예외가 아니라 잘못된 값과 차이 0이 반환됐다.
- 원인: pandas 평균이 binary64로 반올림된 뒤 `float - int`에서도 보고 정수가 float로 반올림돼 차이가 사라진다. 실제 float 변환 왕복에서 `int(float(9007199254740993)) != 9007199254740993`이다.
- 정상 통제 `[2,4]`, 보고 `3`, 오차 `0`은 정확한 값 `3.0`과 일치를 반환했다.
- 이는 현재 허용 숫자형 함수의 합성 경계다. 현재 등록된 실제 나이 자료에서 동일 문제가 발생했다거나 비현실적으로 큰 나이를 올바른 과학 자료라고 주장하지 않는다.

### N10 — 선언한 오차보다 넓은 고정 1e-12

- 입력 평균 `5e-13`, 보고 `0`, 허용오차 `0` 또는 `1e-13`.
- 실제 finals/core 양 경로 모두 일치로 판단했다. 0 오차 본 실험에서 `delta=5e-13`, `within_tolerance=True`, 분모 일치이며 후속 회귀에서 `1e-13`도 동일 결함을 재현했다.
- 원인: `math.isclose(delta, tolerance, abs_tol=1e-12)`는 오차 0/1e-13도 그보다 넓은 바닥 오차로 해석한다.
- 정상 통제 정확한 0은 일치했다. 기존 의도인 계산 `0.8`, 보고 `0.7`, 허용오차 `0.1` 경계도 양 경로에서 정상 일치했다.

### N03와 기타 결과의 보호 경계

서로 다른 정수 문자열 `9007199254740992`/`9007199254740993`은 filter_mask에서 모두 선택돼 평균 10 대신 20이 반환됐다. 숫자 자체의 차이가 1이므로 문자열 라벨의 의미를 별도로 가정하지 않아도 atol=1e-12보다 크다. 그러나 본 실험의 올바른 등록 분모는 1이어서 실제 `denominator_matches=False`였다. 최종 관문은 이 조건을 검사하므로 최종 통과 결함으로 보고하지 않는다.

앞자리 0·퍼센트·boolean alias 사례도 평균/선택행 변화는 관측했으나 분모가 불일치했다. 이들은 열별 사전 없이 서로 다른 코드라고 가정한 의미 경계와 기존 정상 숫자/이진값 정규화 의도를 구분해야 한다. 숫자 `1`과 `1.0`, 사전에서 같은 이진값으로 정의한 true/1/yes의 정상 통제는 유지한다.

null/NaN은 finals에서 `MISSING_OR_NONNUMERIC_OBSERVATION`, inf는 `NONFINITE_OBSERVATION`으로 차단됐다. core의 직접 descriptive/verify는 결측을 제거할 수 있어 missing_policy=error가 direct core까지 전달되지 않는 차이가 관측됐지만 finals 가드가 차단한다. 빈 집단 row_count=0은 core에서 가능하고 finals는 `NO_OBSERVATIONS_AFTER_FILTER`로 차단한다. 유한 입력 `[1e308,1e308]`의 평균은 중간 합 overflow로 양 경로에서 차단됐다. 이들을 잘못된 성공 수치 반환으로 합산하지 않는다.

중복 p1/p1/p2의 나이 10/10/20은 행 평균 13.333333333333334가 반환되고 분모 3이 일치했다. 개인 동일 가중의 평균 15와 다르다. 행 평균 산술 오류가 아니라 관측 단위·중복 정책이 계산 계약에 표현되지 않는 입력 위험이며 사람 2명이라는 의미를 기계가 확인한 결과가 아니다.

## 최소 수정 위치와 정책

1. `[finals/finals_pipeline.py:184–185](https://github.com/twozero3213-beep/nais-ai-hackathon-finals/blob/a6729178963392249b14c9dfbd93bf28704262a4/finals/finals_pipeline.py#L184-L185)`와 `[core/verifier.py:63–70](https://github.com/twozero3213-beep/nais-ai-hackathon-finals/blob/a6729178963392249b14c9dfbd93bf28704262a4/core/verifier.py#L63-L70)`를 하나의 공통 수치 비교 함수로 결속한다. 두 곳을 따로 고치면 승인 전 미리보기와 승인 후 core 검사가 달라질 수 있다. 새 함수의 지문도 실행 provenance의 코드 목록에 포함한다. 이 턴은 타 검수 선점 때문에 제품 수정 pending이다.
2. 보고 정수·오차를 먼저 float로 바꾸지 않는다. 명백히 표현 손실이 있는 정수는 float 변환 왕복 검사로 `PRECISION_UNSUPPORTED`를 반환하고 일치·SUPPORTED를 만들지 않는다. 임의의 `abs(x)>2^53` 범위 차단 대신 해당 값의 실제 왕복 손실을 검사한다. 이 검사는 현재 N08의 손실 원인을 잡지만 모든 큰 수 평균의 정확성을 보장하는 일반 통계 해결책은 아니다.
3. 비교의 공개 숫자 표현 정책은 `abs(Decimal(str(actual)) - Decimal(str(reported))) <= Decimal(str(tolerance))`로 명시하는 안을 권고한다. int는 원형 그대로 보존한다. Decimal 생성 전에 유한한 숫자·bool 제외·오차 비음수를 확인한다. 입력 숫자를 Decimal로 다시 쓰는 통계엔진을 도입하는 제안이 아니라 반환값과 보고값의 비교 경계 정책이다.
4. 이 정책은 `0.8 - 0.7 = 0.1`을 decimal 표현에서 정확히 비교해 `0.1 <= 0.1`로 유지한다. 선언 오차 0에서는 decimal 표현의 차이가 0이어야 하며 `5e-13 <= 0` 또는 `5e-13 <= 1e-13`은 거짓이다. 고정 `1e-12` 바닥이나 이를 숨기는 상대오차를 추가하지 않는다. 계산값 `0.30000000000000004`와 보고 `0.3`, 오차 0은 이 정책상 불일치다. 이진 오차를 허용하려면 계약의 명시적 오차로 표시하며 0을 몰래 넓히지 않는다.
5. 정규화의 큰 정수 충돌은 `[core/normalization.py:39–56](https://github.com/twozero3213-beep/nais-ai-hackathon-finals/blob/a6729178963392249b14c9dfbd93bf28704262a4/core/normalization.py#L39-L56)`에서 numeric float 변환과 np.isclose를 함께 재검토한다. 숫자 표현 `12`/`12.0` 동치는 유지하되 값 차이 1이 정밀도 손실로 0이 되지 않도록 원형을 보존해야 한다. 앞자리 0/퍼센트/별칭의 범주 정책 변경은 별도 의미 계약이며 이번 정밀도 패치에 묶지 않는다.

이 제안은 아직 제품에 적용하거나 교정 후 회귀를 실행하지 않았다. 현재 7개 실패는 수치 결함을 재현한 교정 기대의 실패이며 ‘수정 완료’ 성과가 아니다.
