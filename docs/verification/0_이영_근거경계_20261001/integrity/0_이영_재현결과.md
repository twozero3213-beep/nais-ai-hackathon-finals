# 합성 종단 보고서 무결성 점검

승인 진입점은 실제 원자료로 평균 20을 다시 검산해도, 입력 보고서의 계산 표시값 999를 승인 결과에 그대로 남겼다. 실제 산술 엔진이 999를 검증한 것은 아니다. 계산 성공 여부·분모·엔진 표시 변조도 승인 출력에 보존되었다. 이는 승인 보고서 출력 무결성 결함이며, 새로운 과학적 주장에 대한 자동 의미 승인이나 모델 오류를 입증하는 실험이 아니다.

고정 제품 커밋은 `a6729178963392249b14c9dfbd93bf28704262a4`. 입력·기대 경계는 2026-10-01 05:29:03.895679 KST에 봉인하고, 실제 함수는 05:29:21.365905–05:29:50.785386 KST에 실행했다. 원본 제품 파일은 수정하지 않았다. LLM 호출·네트워크 시도·업무 함수 대체·실제 사람 결정은 모두 0이다.

## 실행 범위와 입력

실제 `run_case_manual`, `approve_report`, `export_report`, `reopen_report`, `recheck_changed_input`를 가져와 호출했다. 제품에는 `save_report` 함수가 없다. 앱의 저장 경로는 `export_report`가 만드는 JSON의 다운로드이며, 이번 실험에서는 반환 JSON을 전용 폴더에 저장해 다시 읽었다.

제품 데이터 경로를 바꾸는 `finals_cases.REPO_ROOT`, `finals_cases.REGISTRY`만 전용 합성 fixture로 격리했다. CSV는 A집단 10·30세, B집단 40세이며 A집단 평균은 20이다. 원문·등록 명세도 합성 자료이다. `confirmed=True`는 실제 승인 함수의 요구 인자로 직접 호출했으며 사유는 `synthetic local test reviewer`로 명시했다. 실제 사용자나 심사위원의 결정은 아니다. 승인 상태·주체를 강제로 만드는 우회 함수나 가짜 모델은 사용하지 않았다.

## 사유·주체·엔진 경계

A05의 미확정 승인 메타데이터는 실제 함수가 덮어쓰고, 사유는 명시적으로 전달한 문자열로 저장했다. 실제 함수의 actor는 `HUMAN_USER` 고정 표식이며 로그인 신원이나 암호학적 사용자 서명이 아니다. E04는 가져온 과거 사유를 변조하기 어렵다는 주장을 반증하지만, 가져온 승인 권한은 비활성이라 승인 우회라고 부를 수 없다.

B07은 보고서의 기록된 `code_commit`·코드 지문·실행 provenance 필드만 변조했다. 승인 자체는 수용되고 메타데이터는 남았다. 실제 로드된 엔진 코드·알고리즘을 바꾸지는 않았으므로, 엔진 변경 이후의 수치 승인 우회를 재현했다는 주장은 하지 않는다. 실행 환경 확인 UI가 존재한다는 사실과 승인 진입점이 기록된 provenance를 결속 검증한다는 주장은 별개이다.

## 최소 수정·회귀 인계

근거는 [고정 코드 approve_report](https://github.com/twozero3213-beep/nais-ai-hackathon-finals/blob/a6729178963392249b14c9dfbd93bf28704262a4/finals/finals_pipeline.py#L466). `calculation = _calculate(...)` 이후 실제 검산의 성공을 확인하지만 반환 복사본의 `calculation`은 교체하지 않는다. 가져오기 쪽 [reopen_report](https://github.com/twozero3213-beep/nais-ai-hackathon-finals/blob/a6729178963392249b14c9dfbd93bf28704262a4/finals/finals_pipeline.py#L546)는 최신 계산을 대입한다.

제안은 [최소 수정 패치](0_이영_최소수정제안.patch)처럼 승인 성공 확인 후 `result['calculation'] = calculation`, `result['validation'] = validation`을 대입하는 것이다. 본 실험의 R01–R03이 해당 재계산 결과 보존을 실제로 실패했다. validation 추가 대입은 읽기 검토에서 얻은 일관성 보완 제안이며, 별도 변조 실행 증거로 제시하지 않는다.

[회귀 제안 실행기](0_이영_integrity_regression.py)는 동일 R01–R03을 실제 함수로 다시 실행해 승인 출력의 계산 전체가 원자료 재계산 결과와 같은지 확인한다. 이 별도 실행기는 아직 실행하지 않았으며, 최소 패치 역시 제품에 적용하지 않았다. 보호 경로의 IMPORTED_REVIEW/active=false도 확인한다. 부모가 다른 기술검수 종료 후 최신 통합본에서 적용·실행할 수 있다.
