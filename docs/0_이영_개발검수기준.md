# 근거관문 개발 검수 기준 — 담당 0

변경은 문제를 재현하고 최소 범위를 고친 뒤 관련 검사를 통과해야 완료다. GitHub 반영과 배포 화면 확인은 별도 상태로 기록한다. 계획, 코드 존재, 모의 실행, 실제 모델 실행, 사람 승인, 논문 전체 재현을 구분한다.

## 설계와 재사용

- 기존 계산 엔진·자료 경로·개인정보 탐지기를 재사용한다. 같은 규칙의 별도 정규식이나 계산 함수를 만들기 전에 기존 구현과 차이를 확인한다.
- 외부 응답은 공급자 어댑터에서 정규화한다. 승인·과학 계산·보고서 경계에서 허용된 명세를 다시 검증하고 모르는 값은 보류한다.
- 방법·열·필터·분모·결측·단위 여섯 조건을 보존한다. `null`, 미해결 조건, 중복 필터 열을 정상값으로 치환하지 않는다. 인용이 원문에 있다는 검사는 의미적 타당성이나 사람 승인을 대신하지 않는다.
- 단위·반올림·결측·분모의 의미를 숨기는 암묵적 형 변환을 피한다. 원 입력과 봉인 기대값은 수정으로 덮어쓰지 않는다.
- 기능·화면·운영자 정책을 분리하고, 경계의 실패 이유와 책임을 명시한다. 새 조건 계약은 원 봉인 프로토콜과 수정 실행기 식별자를 함께 기록한다.

## AI 윤리·개인정보·권한

- 질문·문헌 발췌·후보는 신뢰하지 않는 데이터다. 문서의 지시문이나 모델 문자열을 코드·도구·사람 승인으로 실행하지 않는다.
- 모든 공급자의 전송 직전과 모델 응답의 재전송·저장 전에 동일한 민감형태 검사기를 적용한다. 탐지 시 원문 대신 오류 종류만 남긴다.
- 공통 로그는 민감 문자열을 제거하되 안전한 사건 식별자·상태·검산 수치를 보존한다. 정제는 표시용 사본에 수행하여 원 증거·서명·지문을 바꾸지 않는다.
- Enum 역할과 문자열 역할을 일관되게 처리한다. 등록되지 않은 역할과 알 수 없는 권한은 거부한다. 화면에서 버튼을 숨기는 것만으로 권한 검사를 대신하지 않는다.
- 이름·소속 같은 자유 문장, 공급자 보관 정책, 승인자 신원 인증의 한계는 별도로 공개한다. 형태 검사 통과를 개인정보 보호 전체 인증으로 표현하지 않는다.
- 합성 사례와 실제 논문 사례, 등록된 조건 재진술과 새 조건 발견, 산술 일치와 과학적 타당성을 구분한다. 미실행·실패·동률·패배도 보존한다.

## 구현과 회귀

- 먼저 재현 반례를 확인하고 정상 경로와 함께 검사한다. 실패한 새 입력에 이전 성공 결과가 남지 않도록 상태를 초기화한다.
- 민감형태 검사·권한 검사는 입력 우회와 응답 우회를 각각 확인한다. 모의 공급자 시험은 실제 외부 연결을 금지하고 유료 실행 증거로 세지 않는다.
- 변경 이유·영향·검증 방법·실제 결과는 인접 주석과 CHANGELOG에 기록한다. 원작성 시각을 확인하지 못하면 미확인으로 표시하고 실제 검토 시각을 덧붙인다.
- `python tools/check_finals_metadata.py`와 변경 관련 회귀를 실행한다. Linux CI 결과와 로컬 결과, 서로 다른 시험 묶음은 합산하지 않는다.

## 통합과 배포

- 다른 작업자의 선점을 확인하고 독립 사본에서 수정한다. push 직전 원격 변경을 다시 포함하고 강제 push나 팀원 변경 삭제를 하지 않는다.
- 담당 0의 업로드는 `[0 이영]`, VERSION=0이며 다른 사람의 실제 담당·시각·출처 기록은 유지한다.
- 원격 포함 SHA를 확인하고, 배포 화면의 새 고지·변경 차단·실응답 재생·보고서 재열기를 실제 확인한다. 소스에 존재하는 기능을 배포 완료로 표시하지 않는다.
- 공식 제출 2026-10-01 09:20 KST와 팀 동결 목표 06:20 KST를 구분한다. 영상·발표자료·배포·코드가 같은 확인 범위를 설명해야 한다.

이 기준은 기술 검수의 완료 조건이다. 기관 실증, 운영진의 자료 재사용 허용 여부, 승인자 인증, 일반 모델 대비 성능과 장기 비용 측정은 별도 증거가 필요하다.
