2. 혁신 설계와 한 문장 차별점

**한 문장:** “근거관문은 논문의 수치를 다시 계산하고, 자료나 조건이 바뀌면 그 결론을 다시 쓸 수 있는지 확인하는 검증 에이전트입니다.”

S1 역할 분리와 S2 변경 재검증을 핵심으로 구현하고, S3 동일 조건 비교와 S4 AI 기여도 분리를 같은 8개 사례에서 실행한다. 범위는 **행 수·단일 열 평균·동등 조건 필터**다. 새 모형·논문 검색 확대·기관 운영은 대회 후로 둔다. 제한된 방법으로 원문 조건을 실제 연결하는 것이 함수 수를 늘리는 것보다 I3와 F2를 함께 증명한다.

LLM(엘엘엠·대규모 언어 모델)은 조건 후보를 제안한다. 결정적 계산 엔진은 수치를 계산한다. 비평 모델은 후보·원문·계산 사이의 불일치를 지적한다. 연구자는 의미 연결과 최종 사용 여부를 판단한다. 비평 모델이 동의해도 사람 승인 상태는 변하지 않는다.

| 단계 | 연결 설계·재사용 | 멈춤 조건 |
| --- | --- | --- |
| 입력 | 등록된 원문·위치·CSV(씨에스브이·쉼표 구분 표 파일)만 읽고 SHA-256(에스에이치에이 이오육·파일 지문)을 기록 | 허용 경로 밖, 크기 초과, 지문 불일치, 위치 없음 |

추출 JSON(제이슨·구조화 데이터) 계약 파일은 [extraction.schema.json](extraction.schema.json)이다. 필드는 claim_id(클레임 아이디·주장 식별자), variable(배리어블·변수), filters(필터스·대상 조건), missing_policy(미싱 폴리시·결측 처리), missing_tokens(미싱 토큰스·결측 표기), denominator(디노미네이터·분모와 대상 범위), method(메서드·통계 방법), reported_value(리포티드 밸류·논문 보고값), unit(유닛·단위), source_location(소스 로케이션·원문 위치), field_evidence(필드 에비던스·필드별 근거), unresolved다. 필터 []는 필터가 없다는 근거가 있을 때만 쓴다. 알려지지 않은 조건은 null로 둔다. 인용은 위치가 확인된 실제 원문 구절이다.

JSON Schema(제이슨 스키마·구조 검증 규격)의 형식 검사는 [공식 규격](https://json-schema.org/draft/2020-12/json-schema-validation)을 따른다. 형식 통과는 원문 의미나 분석 타당성의 증거가 아니다. HTML(에이치티엠엘·웹 문서) 위치를 PDF(피디에프·전자 문서)의 가짜 쪽 번호로 바꾸지 않는다. 구현된 proposal_intake의 쪽 번호 계약과 충돌하면 별도 위치 어댑터를 구현한다. 지원하지 않는 결측 표기는 현재 구현을 확인해 명시적으로 거절한다.

일반 AI와의 3줄 비교:

- 일반 AI도 같은 원문·CSV·읽기 및 산술 도구로 정확한 계산과 보류를 할 수 있다. 실제 결과로 비교한다.
- 우리 경로는 입력 지문·계산 조건·원문 위치·실행 기록·승인 상태를 하나의 주장에 연결한다.
- 자료나 조건이 달라지면 결과 재사용을 막고 영향받는 주장만 재검산하며, AI 후보와 사람 판단을 별도 상태로 관리한다.

현실적인 사용 장면: 연구실의 대학원생이 공동저자의 수정 CSV를 받은 뒤, 발표 자료의 표본 수와 평균을 다시 확인한다. 같은 파일명이라도 내용이 달라졌음을 감지하고 영향을 받는 두 주장만 다시 검산한다. 원문에서 제외 기준을 찾지 못하면 지도교수에게 그 조건만 확인 요청한다. 이는 사용 장면 **가정**이며 실제 연구자 인터뷰·절감 효과는 미측정이다.

C03·C04·C06은 합성 규칙 시험이며 실제 논문 오류 사례로 발표하지 않는다. C07·C08은 등록 사례의 사전 고정 변형으로 원본 파일을 수정하지 않는다. C08은 보수적인 바이트 검사 비용도 함께 드러낸다. 일반 AI가 내용 동일성을 정확히 설명하고 등록 결과 대신 새 근거를 제시하면 성공으로 기록한다.

세 조건은 일반 AI 단독 / LLM 없는 우리 경로 / LLM 있는 우리 경로다. 일반 AI에도 같은 원문·CSV·질문·등록 결과·허용된 읽기/계산 도구를 제공한다. 두 AI 조건은 같은 모델과 입력 범위, 사례당 120초·최대 두 호출·호출당 출력 1,800토큰 상한을 사용한다. 수동 조건은 같은 자료에서 사람이 후보를 작성하고, 준비·수정·판정 시간을 기록한다. 사람 검토 상한은 모든 조건에 120초로 통일한다. 준비 시간을 제외한 시스템 시간과 전체 시간 모두 보고한다.

모델 ID(아이디·식별자), 공급자, 지출 상한은 미확정이다. 공개 여부·권리가 확인된 최소 입력으로 제한하고, 외부 전송·비용 조건이 확정된 뒤 실행한다. 키는 서버 비공개 설정에서 읽으며 로그·원출력·화면에 넣지 않는다. 일반 AI에 자유 코드 실행을 허용하지 않되 같은 제한 산술 도구는 제공한다.

실행 전 순서:

1. 사례별 원문·CSV·질문·등록 명세와 기대 판정 파일을 만든다. 모든 조건에서 같은 자료를 받게 한다. 정답 파일은 어떤 모델에도 전달하지 않는다.
2. 조건·기대값·허용 보류 사유를 계산 담당과 검증 담당이 교차 확인한다. 자료 변경에 대한 정확한 새 계산·근거 검토도 허용 답에 포함한다.
3. tools/compare_exploratory.py의 freeze를 재사용해 입력·질문·기대 판정 지문과 코드 커밋을 고정한다. 현재 스크립트의 두 조건 제한은 별도 3조건 집계기로 확장하고, 승인 판정은 자동 생성하지 않는다.
4. manifest(매니페스트·파일 목록)의 지문을 먼저 Git에 올린 뒤 실행한다. planning-artifact-hashes.json은 계획 파일의 지문이며 실험 봉인이 아니다.
5. 새 세션으로 각 사례·조건을 실행한다. 지연·실패·패배 사례를 모두 보존한다. 시간 초과도 결과다.
6. 결과를 보고 사례·정답을 바꾸지 않는다. 구현 오류 수정·재실행은 새 실행 번호와 코드 커밋으로 전 시도를 보존한다.

기록: 최종 판정, 보고값/계산값, 원문 위치와 인용의 유효성, 보류 필요/실제 보류, 변경 뒤 결과 재사용, 근거 없는 수치, 시스템·준비·검토 시간, 수동 입력·수정 필드 수, 호출·실제 사용 토큰·실제 비용, 실패 이유, 원출력·도구 로그 지문. 비용 영수증이 없으면 **미측정**으로 두고 무료/0원이라고 쓰지 않는다.

AI 기여도 분리 비교인 Ablation(어블레이션·구성 요소 제거 비교)은 수동 경로와 AI 경로의 조건 입력 개수·수정 개수·추출 필드 정확성·전체 소요 시간으로 평가한다. 필드 정확성은 사전 고정 참조 조건을 기준으로 계산한다. 수동으로 제공한 조건을 AI가 추출한 것으로 세지 않는다. AI 경로가 더 느리거나 수정을 늘리면 그대로 발표한다.

저장된 실제 호출 원출력이 없으면 그 단계는 건너뛴다. 캡처 순차 재생을 조작 녹화라고 말하지 않는다. 계획상 120초를 넘어가면 자료 변경과 보고서의 검증된 화면을 먼저 보여주고 실패 사유를 말한다.

시연 설정: app.py에 NAIS_DEMO_MODE(나이스 데모 모드·시연 화면 설정)를 추가할 계획. core/research_demo_ui.py의 render_guided_demo와 장면 흐름을 재사용한다. 연구 시작·검산·보고서 세 기능을 노출하고 팀 관리·대규모 평가·예약 과제·외부 검색·기관 API·임의 파일 업로드를 숨긴다. 시연 설정은 접근 권한·사람 승인·비밀값 검사를 우회하지 않는다. 숨김만으로 안전 검사를 대신하지 않는다.

발표 당일 점검표:

- 네트워크: 발표 위치에서 접속·응답 시간을 확인하고 테더링 대체 연결 준비.
- 로그인: 올바른 시연 계정, 세션 만료 확인, 예비 기기 로그인 완료.
- 키 설정: 서버에서 키 존재·공급자 권한·호출 한도 확인. 키 값은 화면·보고서·로그에 표시하지 않음.
- 브라우저: 발표 탭·로컬 탭·보고서 탭 순서 고정, 알림 끄기, 불필요한 개인 탭 닫기.
- 화면: 프로젝터 해상도·배율·한글 글꼴·작은 글씨·노란 보류 안내 가독성 확인.
- 전원: 충전기 연결·배터리·예비 기기·연결 어댑터 준비.
- 오프라인: 동일 코드·입력·보고서·실제 녹화 파일을 두 기기에 보관, 현장에서 소리·재생 확인.
- 기능: 세 장면·모든 노출 버튼·보고서 다운로드·재열기·지문 변경·승인 필요 상태 확인.
- 증거: 비교 실패 포함 원출력, 입력 봉인, 동결 커밋, 담당 번호, 제출 파일 목록 대조.

본선 작업 증거는 GitHub 커밋 목록, CHANGELOG의 이유·검증, 입력/원출력 지문, 동결 커밋을 함께 보여준다. 소스 자료의 작성일과 본선 통합·추가 기능의 시각을 구분한다. 담당 버전은 이영 0·이채우 1·임도윤 2·조지현 3이다. 커밋 시각을 새로 조작해 개발 시점의 증거로 쓰지 않는다.
