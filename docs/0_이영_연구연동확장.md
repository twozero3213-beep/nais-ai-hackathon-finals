기존 논문 검색에서 발견한 DOI를 원자료의 고정 버전과 연결하고, 정정·철회 공지를 다시 대조할 수 있게 했다. 공개 메타데이터만 조회하며 파일 수신·계산 실행·사람 승인은 기존 근거관문 절차에서 수행한다. 별도 MCP로 Codex와 Claude Code에 같은 7개 도구를 제공한다. 웹 화면의 새 버튼과 이 도구를 연결하는 작업은 이번 변경 범위에 포함하지 않았다.

| 도구 | 기능 | 실제 확인 |
|---|---|---|
| `integration_catalog()` | 제공자·입력 예시·기능 경계 | stdio 초기화와 7도구 목록 |
| `repository_record(provider, identifier)` | Zenodo·Figshare·Harvard Dataverse의 DOI·버전·라이선스·접근 제한·공급자 체크섬 | 3곳 HTTP 200; 파일 정보 각각 1/2/9개 |
| `search_repository(provider, query, limit)` | Zenodo/Dataverse 키워드 검색, Figshare 정확한 DOI 검색 | Zenodo total 5 중 2건 |
| `publication_updates(doi)` | Crossref production의 update-to/updated-by와 공지 DOI 역연결 대조 | 우려 표명·철회 공지 각 1건 및 원논문 역연결 HTTP 200 |
| `pubmed_record(pmid)` | PMID/DOI/PMCID와 정정·철회 관계 | PMID 23193287의 DOI/PMC 연결 HTTP 200 |
| `scholarly_feed(provider, limit)` | arXiv·bioRxiv·KISTI 요청 시 RSS/Atom/RDF 조회 | 3곳 HTTP 200, 각각 유효 항목 3건 |
| `scholar_discovery(query)` | Google Scholar 검색 링크와 원출처 추적 단계 | 링크 생성; 직접 스크래핑 없음 |

실제 공개 호출: 2026-10-01 00:55:17~00:55:30 KST. bioRxiv의 RSS 1.0/RDF 형식을 보완한 뒤 01:07:59 KST에 같은 stdio 실행기로 HTTP 200·30건 중 3건을 확인했다. arXiv 피드 전체 759건, KISTI 10건은 당시 관측값이다. RSS 수집은 요청 시 실행한다.

```python
from core.repository_extensions import repository_record, search_repository
from core.publication_extensions import publication_updates, pubmed_record
from core.scholarly_feeds import get_feed

repository_record("zenodo", "3960218")
repository_record("figshare", "10.6084/m9.figshare.963443.v2")
repository_record("dataverse", "10.7910/DVN/TUPVFG@1.0")
search_repository("zenodo", "palmerpenguins", limit=2)
publication_updates("10.1111/evo.14483")
pubmed_record("23193287")
get_feed("arxiv", limit=3)
```

선택형 MCP 실행: `python -m pip install -r requirements-research-mcp.txt` 후 저장소 루트에서 `python -u -m tools.research_extensions_mcp`. 확인한 환경은 Python 3.13.5/FastMCP 2.14.7/MCP 1.30.0이다. 양쪽 클라이언트가 공유하는 `NAIS_PUBLIC_RATE_DB` 경로를 지정하면 호출 간격을 같은 SQLite 파일로 조정한다. 이 파일에는 제공자 이름·다음 요청 시각만 저장하며 원문 응답은 저장하지 않는다. arXiv는 3.1초 간격, 다른 연결은 1초 간격이다. arXiv는 별도 `.arxiv-connection` SQLite 배타 잠금을 HTTP 종료까지 유지하므로 두 MCP 프로세스의 느린 응답도 연결을 중첩하지 않는다. 잠금 획득 대기는 합산 30초이며 빈 잠금 테이블에 요청·응답 내용은 쓰지 않는다. 이 조정은 같은 경로를 사용하는 프로세스에 한정되므로 별도 arXiv 클라이언트의 요청도 합산해서 관리해야 한다. [arXiv 공식 이용 조건](https://info.arxiv.org/help/api/tou.html).

`response_sha256`는 HTTP 응답 바이트의 지문이다. 파일 항목의 MD5/SHA는 공급자가 광고한 값이며 실제 내려받은 바이트 검증이 아니다. `verified/verification_pass/approved`는 false를 유지한다. 정정 정보 미검출은 철회 없음의 증명이 아니다. concept DOI와 고정 버전 DOI, 공급자 계산 지문과 업로더 제출 지문, 발행일과 조회 시각을 구분한다. 날짜의 시간대가 불명확하면 임의 UTC 시각을 만들지 않는다.

Google Scholar는 논문·사전 공개본·서지정보를 색인한 검색 서비스다. 제목·인용수·검색 순위는 발견용으로 쓰고, 실제 출판사/저자 저장소의 논문 버전과 Data availability의 원자료 식별자를 대조한다. Google은 대량 접근을 제공하지 않는다고 안내하므로 이 모듈은 고정 검색 링크만 생성한다. [공식 검색 도움말](https://scholar.google.com/intl/en/scholar/help.html).

로컬 두 코딩 클라이언트에는 공식 무키 검색 MCP Exa·Parallel·You.com·Tavily·Firecrawl도 등록했다. Exa·Parallel·You.com은 실제 검색 결과를 반환했다. Tavily는 `monthly_cap_reached_bonus_eligible`, Firecrawl은 도구 오류를 반환하여 검색 성공으로 기록하지 않았다. 이는 클라이언트 설정이며 공개 웹 앱에 해당 검색 MCP가 배포되었다는 뜻은 아니다. 유료 계정·키·결제·자동 권한 승인은 추가하지 않았다. [Exa](https://exa.ai/docs/get-started/exa-mcp), [Parallel](https://docs.parallel.ai/integrations/mcp/quickstart), [You.com](https://you.com/docs/agents/mcp-server), [Tavily](https://docs.tavily.com/documentation/keyless), [Firecrawl](https://docs.firecrawl.dev/mcp-server/keyless).

공식 원출처: [Zenodo API](https://developers.zenodo.org/), [Zenodo DOI 버전](https://support.zenodo.org/help/en-gb/1-upload-deposit/97-what-is-doi-versioning), [Figshare API](https://docs.figshare.com/v2/), [Dataverse Native API](https://guides.dataverse.org/en/latest/api/native-api.html), [Crossref Retraction Watch](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/), [PubMed E-utilities](https://www.ncbi.nlm.nih.gov/books/NBK25497/), [arXiv RSS](https://info.arxiv.org/help/rss.html), [bioRxiv 공식 피드 안내](https://www.medrxiv.org/alertsrss), [KISTI RSS](https://www.kisti.re.kr/rss-help/pageView/178).

검증 범위: 신규 모듈의 오류·동일 식별자·버전·라이선스·체크섬 출처·RSS 형식·프라이버시 입력·날짜 처리 회귀시험. 최신 main의 독립 작업본에서 2026-10-01T01:19:03+09:00에 신규 시험 145개 통과(2.21초, pytest 캐시 디렉터리 생성 권한 경고 1개), 본선 메타데이터 검사 PASS/JSON 20개를 확인했다. 실제 API 호출은 위의 공개 식별자 예시에 한정한다. 에이전트 전체 정확도·속도 향상 폭, 본문 수신·논문 재현·AI 비교 16건·실행 중 다른 채팅의 설정 수신은 이번에 측정하지 않았다.
