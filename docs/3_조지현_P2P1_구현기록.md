## 2. 정규 명세 v2 (P2)

`docs/finals-strategy/extraction.schema.json`(v1)의 필드를 그대로 두고 다음을 더했다. v1 파일은 바꾸지 않았다(계획 지문 유지).

| 추가 | 내용 |
|---|---|
| `spec_version` | 2 |
| `method` | `row_count`·`mean`·`ols_regression`·`row_alignment` (v1 `count_rows`는 변환 시 `row_count`) |
| `data_fingerprint`·`tolerance` | 자료 SHA-256, 0 이상 허용오차 |
| 회귀 | `outcome`, `predictors`, `reported{항: {b, se, t}}`, `reported_df` |
| 행 대응 | `data_id_column`, `reference_ids_source` |

- 모든 필드는 항상 존재하고 모르면 `null`이다. `unresolved`가 하나라도 있으면 실행하지 않는다.
- 방법별 필수: 행 수(보고값), 평균(보고값·열·결측 정책·결측 표기), 회귀(결과·예측변수·보고 계수·결측 정책·결측 표기), 행 대응(식별자 열·기준 출처).
- 재정렬 허락은 명세에 넣지 않는다. AI가 제안한 명세가 스스로 승인하지 못하게, 사람이 실행할 때 따로 입력한다.

**형식 3종 대응**

| v2 | 자료 AI 제안 검사기 | 자료 등록 사례 | 변환할 수 없을 때 |
|---|---|---|---|
| `variable` | `column` (행 수는 `__dataset__`) | `column` (행 수는 빈 문자열) | — |
| `row_count` | `row_count` | `count_rows` | 회귀·행 대응은 두 형식 모두 대응 없음 → unresolved |
| `filters[{column, operator:"eq", value}]` | `[{column, value}]` | `{열: 값}` | 등록 형식은 문자열 정확 일치만 → 숫자 값은 unresolved |
| `missing_policy` | `complete_case`만 | `drop`·`error`, 빈 칸만 결측 | 그 밖의 정책·결측 표기는 unresolved |
| `source_location{source_id, locator, quote}` | `evidence{source_page(정수), source_quote}` | `source_location`·`source_quote` | 쪽 번호가 아닌 위치는 제안 형식에서 unresolved |
| `denominator`·`unit` | 필수 | 자리 없음 | 제안 형식에서 값이 없으면 unresolved, 등록 형식에서는 not_carried |

변환 결과는 `convertible`, `target`, `unresolved`, `not_carried`를 돌려준다. unresolved가 있으면 `target`은 `null`이라 반쪽짜리 결과를 쓸 수 없다. not_carried는 대상 형식에 자리가 없어 호출 측이 따로 보관해야 하는 값(예: `source_id`)이다.

## 3. 최소 실행 경로 (P1)

순서: 명세 검사 → 자료 지문 대조 → CSV 해석 → 필터 → 계산 → 판정 → 기록.

| 판정 | 조건 | 이유 코드 예 |
|---|---|---|
| MATCH | 계산값과 보고값 차이 ≤ 허용오차 / 행 대응 일치 / 사람 승인 재정렬 | `COMPUTED`, `ROWS_ALIGNED`, `ROWS_REORDERED_WITH_APPROVAL` |
| MISMATCH | 차이 > 허용오차, 회귀 계수 불일치 | `COMPUTED`, `COEFFICIENT_MISMATCH` |
| NEEDS_REVIEW | 회귀 계수는 맞지만 표준오차·t·자유도가 다름 | `COEFFICIENT_MATCH_OTHER_DIFFERS` |
| BLOCK | 명세 미완성, 자료 바이트 변경, 형식 오류 값, 결측 정책 위반, 열 없음, 식별자 구성·순서 불일치 | `SPEC_NOT_READY`, `STALE_DATA`, `BAD_VALUE`, `MISSING_VALUES`, `ROW_ORDER_REORDER_REQUIRED`, `ROW_MEMBERSHIP_MISMATCH` |

전수 검사에서 찾은 자료의 약점을 이번 코드에서 이렇게 처리했다.

- **형식 오류 값:** `"1,000"`·`"N/A"`처럼 결측 표기도 숫자도 아닌 값은 조용히 빼지 않는다. 문제 행 번호·열·값을 보여 주고 BLOCK한다. 숫자는 엄격한 10진 표기만 받는다(`nan`·`inf`·`1_000`·앞뒤 공백 거부).
- **자유도:** 계수가 맞아도 자유도가 다르면 MATCH가 아니라 NEEDS_REVIEW다.
- **행 대응:** 빠진·남는·중복 식별자와 순서가 다른 위치(최대 20개)를 보여 준다. 재정렬은 승인자와 근거를 모두 입력해야만 진행한다.
- **기록:** 실행 번호·실제 KST 실행 시각·명세 지문·자료 지문·(기준 지문)을 JSON 한 줄로 추가한다. 파일 끝이 줄바꿈이 아니면 손상을 의심해 쓰지 않는다. 이전 결과는 모든 지문이 같을 때만 찾는다.
