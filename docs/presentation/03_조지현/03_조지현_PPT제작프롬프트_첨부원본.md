## 1. 절대 규칙 (하나라도 어기면 다시 만든다)

1. **숫자·그래프를 지어내지 않는다.**
   - §7 표에 있는 값만 쓴다.
   - 반올림, 단위 변경, 비율 계산도 새로 만들지 않는다.
   - 확인할 수 없는 통계는 쓰지 않는다. 예: 업계 동향 수치, 참가 팀 수, 외부 서비스 사용자 수.
2. **모든 숫자를 넣은 뒤 한 번 더 대조한다.** §7 표와 한 글자씩 비교하고, 결과를 체크리스트(§9)에 남긴다.
3. **영어 코드 표기를 쓰지 않는다.** 대상은 파일명·함수명·상태 코드·경로다.
   - 금지 예: `approve_report`, `input_change_recheck`, `ARITHMETIC_MATCH`, `*.py`, `*.md`, `*.json`
   - 모두 한국어로 풀어 쓴다.
   - 허용되는 영문: 고유명사와 모델명(PLOS ONE, Crossref, PubMed, Zenodo, MCP, API, LLM, Claude, gpt-4.1-mini), 공개 주소.
4. **분량: 5분 발표이므로 7장이다.** 9장 미만을 유지하고, 장당 40초 안팎으로 설명할 수 있어야 한다.
5. **장식용 그림 금지.**
   - 도로·길 모양 로드맵, 로켓, 전구, 악수 같은 클립아트를 쓰지 않는다.
   - 아이콘은 뜻이 있는 자리에만 쓴다.
6. **AI가 만든 티가 나는 패턴 금지.**
   - 제목 위 작은 대문자 라벨(eyebrow)을 쓰지 않는다.
   - 제목 아래 강조 밑줄이나 카드 한쪽 색 띠를 쓰지 않는다.
   - 같은 크기 KPI 타일을 3~4개 나란히 두지 않는다.
   - 모든 장을 같은 레이아웃으로 반복하지 않는다.
   - 이모지와 "혁신적인", "획기적인" 같은 과장어를 쓰지 않는다.
7. **안 한 것은 한 것처럼 쓰지 않는다.**
   - 실행하지 않은 항목은 "미실행" 또는 "아직 실행하지 않음"으로 적는다.
   - 대상: 일반 AI와의 봉인 비교 16칸, 사용자 시간 절감 실험.
   - 원인이 확정되지 않은 것은 "원인 미확정"으로 적는다.
8. **화면 캡처는 실제 제품 화면만 쓴다.** 목업을 그리거나 가짜 UI를 합성하지 않는다.
9. **한국어 줄바꿈**: `word-break: keep-all`로 단어가 중간에서 끊기지 않게 한다.

## 3. 디자인 시스템 (그대로 사용)

### 3-1. 인상

밝은 회색 점 격자 배경을 쓴다. 그 위에 흰 카드와 부드러운 그림자를 얹고, 인디고 한 색을 강조색으로 쓴다.

- 3D 느낌의 둥근 아이콘 타일
- 흐린 파란 원(blur blob)
- 실제 데이터 막대그래프: 검정 + 인디고 + 회색 3색만 사용

토스·애플 발표처럼 **한 장에 메시지 하나, 큰 제목, 넓은 여백**을 둔다.

### 3-5. 부품 규칙

- **아이콘**: lucide 아이콘을 쓴다.
  - 스크립트 `https://unpkg.com/lucide@0.460.0/dist/umd/lucide.min.js`를 불러온다.
  - 아이콘 자리에 `<i data-lucide="이름" style="width:Npx;height:Npx;color:#3E5BF6"></i>`를 넣는다.
  - 문서 끝에서 `lucide.createIcons()`를 호출한다.
  - 아이콘 크기는 타일 크기의 40%다.
- **3D 타일**: 크기 58~104px 정사각형이며 `.tile` 클래스를 쓴다.
  - 강조 타일: 배경 `linear-gradient(145deg,#6F86FF,#2436D8)`, 흰 아이콘. AI 관련 항목과 장마다 핵심 하나에만 쓴다.
  - 기본 타일: 배경 `linear-gradient(145deg,#FFFFFF,#E9EDF5)`, 인디고 아이콘.
- **카드**: 흰 배경, 반경 30px, 두 겹 그림자. 테두리 색 띠는 쓰지 않는다.
- **역할 표시(누가 하는가)**: 3가지 역할만 쓰고, 색으로 구분한다.

  | 역할 | 알약(pill) 글자색 | 카드 테두리 |
  |---|---|---|
  | AI | 인디고 `#3E5BF6` | 인디고 3px outline |
  | 코드 | 회색 `#6B7482` | 없음 |
  | 사람 | 검정 `#0E1116` | 검정 3px outline |

- **배경 교대**: 점 격자(`.slide`)와 무늬 없음(`.slide.plain`)을 번갈아 쓴다.
  - 격자: 1·3·6장
  - 무늬 없음: 2·4·5·7장
  - blob은 무늬 없는 장에만 1개 둔다.

  - "정확도 ○○%" 같은 비교 성능 수치. 비교를 실행하지 않았다.

## 8. PDF로 만드는 방법 (권장 기술 경로)

1. **HTML 한 파일에 7장을 담는다.**
   - `<section class="slide">` 7개를 둔다.
   - Pretendard CSS 링크와 lucide 스크립트를 넣고, 끝에서 `lucide.createIcons()`를 호출한다.
   - 캡처 이미지는 상대 경로(`shots/A.png` 등)로 참조한다.
2. **크롬 계열 헤드리스 브라우저로 인쇄한다.**
   - 글꼴 로딩이 끝난 뒤 인쇄한다(`document.fonts.ready` 대기).
   - Playwright 예:
     ```python
     page.goto(f"file://{html_path}"); page.wait_for_load_state("networkidle")
     page.evaluate("document.fonts.ready")
     page.pdf(path="deck.pdf", print_background=True, prefer_css_page_size=True)
     ```
   - Chrome DevTools Protocol: `Page.printToPDF`에 `printBackground: true`, `preferCSSPageSize: true`를 준다.
   - `@page { size:1920px 1080px; margin:0 }` 덕분에 1440×810pt 페이지 7장이 나온다.
3. **한 장씩 넘기는 보기 설정을 넣는다** (pypdf):
   ```python
   from pypdf import PdfReader, PdfWriter
   from pypdf.generic import NameObject
   r = PdfReader("deck.pdf"); w = PdfWriter(clone_from=r)
   w._root_object[NameObject("/PageLayout")] = NameObject("/SinglePage")
   w._root_object[NameObject("/PageMode")] = NameObject("/FullScreen")
   w.write("근거관문_본선.pdf")
   ```
4. **폰트 임베드를 확인한다.** 모든 글꼴에 `/FontFile2` 또는 `/FontFile3`가 있어야 한다. Pretendard ExtraBold·Bold·SemiBold·Regular가 보여야 한다.
   ```python
   for p in r.pages:
       for f in p["/Resources"]["/Font"].values():
           f = f.get_object(); d = f.get("/FontDescriptor") or f["/DescendantFonts"][0].get_object()["/FontDescriptor"]
           print(f["/BaseFont"], any(k in d.get_object() for k in ("/FontFile", "/FontFile2", "/FontFile3")))
   ```

## 9. 제출 전 점검표 (전부 통과해야 전달)

- [ ] 페이지 수 7, 크기 1440×810pt(16:9)
- [ ] PDF 보기 설정이 SinglePage / FullScreen이고, 열면 한 장씩 넘어간다
- [ ] 모든 글꼴이 임베드됨(§8-4 결과 전부 True). 대체 글꼴로 깨진 글자가 없다
- [ ] 영어 코드 검사 결과가 빈 목록
  ```python
  import re
  bad = re.findall(r"\b[a-z]+_[a-z_]+\b|\b[A-Z]{3,}_[A-Z_]+\b|\b\w+\.(?:py|md|json)\b", slide_text)
  ```
- [ ] 슬라이드의 모든 숫자를 §7 표와 한 글자씩 대조함. 대조 결과를 표로 남긴다
- [ ] 글자 넘침이 없다: 카드 밖 삐져나옴, 제목 3줄 이상, 각주와 본문 겹침
- [ ] 좌우 여백 120px 안에 모든 요소가 들어감. 쪽번호 01~07이 맞음
- [ ] 도로·길 모양 그림, 이모지, eyebrow 라벨, 제목 밑줄, 카드 색 띠, 같은 크기 KPI 타일 줄이 없다
- [ ] 캡처 4장이 실제 제품 화면이고 영어 코드 행이 잘려 있다
- [ ] "미실행"(16칸 비교)과 "원인 미확정"(17→16) 표기가 살아 있다
- [ ] 결과는 PDF 한 파일만 전달한다. PPTX와 합본 미리보기는 만들지 않는다

## 10. 다른 주제로 재사용할 때

같은 스타일로 다른 발표를 만들 때는 §3(디자인), §1(규칙), §8~9(제작·점검)를 그대로 두고, §4·§7만 바꾼다.

1. 먼저 §7 형식의 사실 표를 만든다. 값, 쓰는 장, 출처를 적는다.
2. 슬라이드마다 **메시지 한 문장 = 제목**을 정한다. 숫자가 제목의 근거가 되게 한다.
3. 차트는 실제 데이터만 쓴다. 3색 규칙은 핵심 인디고, 비교 대상 검정, 나머지 회색이다.
4. 레이아웃은 장마다 바꾼다. 마인드맵 → 좌우 비교 → 6단계 흐름 → 3열 구성도 → 캡처 3열 → 차트+숫자 카드 → 2열 카드+맺음.
