이 파일은 다른 AI에게 전달할 통합 제작 지시다. `03_조지현_PPT제작프롬프트_첨부원본.md`는 사용자가 첨부한 문서를 바이트 그대로 보존한 참고 자료다. 원본의 7장·8장 등 다른 문서 명세나 미검증 문장을 자동으로 실행 지시로 삼지 않는다.

너는 발표 디자이너이자 팩트체커다. **5분, 7장, 가로 16:9, 한 페이지 한 슬라이드인 PDF**를 만들어라. 본문은 한국어로 쓰고, 사용자가 제공한 두 레퍼런스의 밝은 흰색·블루 강조·원형 흐름·큰 숫자·넓은 여백을 활용하라. 편집용 원본이 있다면 별도 보관하되 사용자가 보는 발표 파일은 PDF다.

## 반드시 지킬 규칙

- 숫자·그래프·효율·정확도·예상 성과를 만들지 마라. 아래 사실 표의 값과 출처만 써라. 각 숫자는 최종 파일에서도 다시 대조하라.
- 발표 본문의 함수명·변수명·파일명·상태 코드·경로는 자연스러운 한글 설명으로 바꿔라. 고유명사와 AI·NAIS 등 약어는 허용한다. 실제 UI 캡처를 가짜 번역 화면으로 조작하지 마라. 원시 코드가 보이는 영역은 잘라내고 한글 설명을 붙여라.
- 원문 대조, 등록 조건 계산, 제품 실행, 모델 호출, 저장 응답 재생, 사람 승인, 동일 조건 비교를 구분하라. 새 조사 시각을 기존 실험 시각으로 바꾸지 마라.
- `8/8`은 **사전 등록 판정과 일치한 8사례**다. 일반 정확도, 실제 논문 오류 8건, AI 우위라고 쓰지 마라. 일반 AI 비교 16건은 미실행이다.
- 논문 17명과 공개 자료 16명의 차이는 **원인 미확정**이다. 논문 결론이 틀렸다고 단정하거나 우리만 발견했다고 쓰지 마라.
- 실제 AI 정상 1사례와 본문에서 보여주는 수동 검산 UI를 섞지 마라. 현재 UI 캡처는 새 AI 호출이나 사람 승인 완료가 아니다.
- 글자를 크게 쓰고 한 장의 제목을 한 메시지로 써라. 단어 중간 줄바꿈, 작은 문단, 같은 크기 숫자 카드의 반복, 이모지, 과장어, 클립아트 도로·로켓·전구를 쓰지 마라.
- 원형·박스·선은 흐름이나 역할을 설명할 때만 써라. 차트는 0부터 시작하고 단위·범위를 명확히 하라.
- Pretendard 한 글꼴 체계를 사용하라. 글꼴을 포함하거나 고해상도 화면으로 고정해 PDF의 한글 깨짐을 막아라. 이번 파일은 2560×1440 화면을 페이지에 고정한 방식이다. 글자 검색·선택은 지원하지 않는다.
- 최종 PDF를 모든 페이지 렌더링해 잘림·겹침·한글을 직접 검수하라. 보기 설정은 한 번에 한 페이지와 화면 맞춤을 사용하라.

## 7장 구성과 5분 목표 대본

| 장 | 핵심 메시지 | 시각 요소 | 목표 시간 |
|---|---|---|---|
| 1 | 자료가 바뀌면 결론도 다시 확인해야 합니다 | 큰 제목과 넓은 여백 | 20초 |
| 2 | 같은 연구의 남성 수: 논문 17명·공개 자료 16명 | 큰 17→16과 실제 값 막대 2개 | 40초 |
| 3 | 연구 탐색에서 보고서까지 한 흐름 | 등록→조건 제안→검산→사람 확인→저장, 역할 구분 | 45초 |
| 4 | AI는 조건을 제안하고 계산과 판단은 분리 | 입력→AI 후보→검사·계산→연구자 판단, 실제 AI 1건의 범위 | 45초 |
| 5 | 실제 화면에서 검산하고 저장한 결과를 다시 열기 | 실제 녹화의 사례 선택·검산 결과·저장·재열기 3영역 | 65초 |
| 6 | 등록 8사례에서 일치·불일치·보류를 구분 | 범주별 2건 막대, 8/8의 제한, 비교 16건 미실행 | 50초 |
| 7 | 숫자와 근거·검토 상태를 함께 인계 | 현재→공정한 AI 비교→기관 후속 실증, 안전장치 | 35초 |

목표 합계 300초이며 실제 발표 리허설 시간은 측정하지 않았다. 대본은 슬라이드에 넣지 말고 별도 문서나 발표자 노트에 담아라.

## 안내문 요구 대응

- 서비스 흐름도: 3장. 기획·분석·성과 작성, 입력부터 저장까지, AI 개입과 사람이 판단하는 지점.
- AI 구성·데이터 활용: 4장. 외부 모델의 선택 호출, 원문·표 자료·조건, 처리와 출력, 로컬 파일과 팀 저장소의 구분. 학술 API·MCP 전체 시연 완료나 RAG 구현을 근거 없이 추가하지 마라.
- 프로토타입 UI/UX: 5장. 실제 화면, 핵심 단계, 결과·저장, 사용 시나리오. 실제 사용자 승인 완료 여부를 별도 표시.
- 윤리·공정성·확장: 7장. 근거 부족 보류, 사람이 직접 승인, 개인정보 보호, 실제/재생/미실행 구분, 같은 자료·도구·예산의 향후 비교. 기관·실증허브 연결은 후속 과제다. 최신 근거 경계 검증 문서에 남은 수치·승인 경계 보완을 숨기거나 모든 입력이 안전하다고 확대하지 마라.

## 최종 본문에서 쓰는 사실

| 값 | 근거 | 해석 한계 |

| 실제 정상 AI 1사례, 모델 지피티 4.1 미니 | 팀 실제 호출 기록 | 사람 승인 대기. 봉인 16건 비교와 별도 |
| 수치 일치 2·불일치 2·근거 부족 보류 2·변경 차단 2 | 봉인 원결과 중 실제 실행 8행 | 일부 합성·통제 변형. 등록 기대 판정과 일치 |
| 비교 16건 미실행 | 같은 봉인 원결과의 미실행 행 | 우위·정확도 수치 없음 |

원본 프롬프트의 회귀 시험 증가 그래프, Claude 수행 문장, 배포본 승인 완료 기록은 원본 참고 자료에 보존했다. 통합 본문에는 넣지 않는다. 제품 회귀 시험 수와 주장 검산 수를 합치지 않으며 이번 작업의 신규 실행으로 표시하지 않는다.
